# Roadmap: VitalSense AI

## Overview

A phased journey from a brownfield Next.js codebase with legacy database redundancies into a secure, state-managed clinical analyzer. We will start by establishing secure agentic reasoning logic and fact-checking guardrails within the LangGraph backend. Next, we will expand conversational nodes to handle progressive follow-ups and custom summaries. Finally, we will refactor client-side state management, polish the dashboard with rich micro-animations, and implement an automated verification suite.

---

## Phases

- [ ] **Phase 1: Agentic Diagnosis Guardrails & Logic** - Implement secure clinical reasoning and evidence-citation structures within LangGraph.
- [ ] **Phase 2: Conversation & Graph Flow Improvements** - Refine conversation and summary nodes to guide diagnostic follow-up prompts.
- [ ] **Phase 3: Clean Client-Side State Management** - Refactor React client states to eliminate concurrency race conditions.
- [ ] **Phase 4: Smooth UI/UX Visual Polish** - Polishing visual panels with rich loading skeletons and transition animations.
- [ ] **Phase 5: Automated Testing & Verification** - Setting up Vitest unit testing and isolated graph simulation checks.

---

## Phase Details

### Phase 1: Agentic Diagnosis Guardrails & Logic
- **Goal**: Implement secure clinical reasoning logic to synthesize conversations/abnormal lab values, cite factual evidence, and enforce medical disclaimers.
- **Depends on**: Nothing
- **Requirements**: FLOW-03, FLOW-04, FLOW-05, FLOW-06
- **Success Criteria**:
  1. LangGraph outputs a personalized medical summary explaining "why it is happening" using active chat data.
  2. The agent strictly cites concrete, factual lab results from the active session.
  3. Every clinical conclusion generated by the agent is appended with a prominent medical disclaimer.
- **Plans**: 2 plans

Plans:
- [ ] 01-01: Build clinical conclusion synthesizer and citation rules inside `lib/agent/nodes/clinical-summary.ts`.
- [ ] 01-02: Implement evidence verification checks and automated disclaimers in `lib/agent/nodes/guardrails.ts`.

---

### Phase 2: Conversation & Graph Flow Improvements
- **Goal**: Refine standard conversation and lab analysis nodes to handle user symptoms and coordinate Q&A loops.
- **Depends on**: Phase 1
- **Requirements**: FLOW-01, FLOW-02
- **Success Criteria**:
  1. Patient can chat about normal health concerns when no PDF is present.
  2. Uploading a PDF successfully triggers the follow-up gathering state.
  3. The agent continues to prompt for relevant symptom details (one question at a time).
- **Plans**: 2 plans

Plans:
- [ ] 02-01: Update conversation node `lib/agent/nodes/conversation.ts` and prompts in `lib/agent/prompts.ts`.
- [ ] 02-02: Refine lab analysis node `lib/agent/nodes/lab-analysis.ts` to manage state transitions correctly.

---

### Phase 3: Clean Client-Side State Management
- **Goal**: Refactor the main interactive dashboard panel state container to ensure safe concurrency and prevent loading race conditions.
- **Depends on**: Phase 2
- **Requirements**: UI-01
- **Success Criteria**:
  1. Unified React state handling active chats, messages, and PDF files.
  2. Absolute zero race conditions or desyncs during rapid file uploads or chat prompts.
- **Plans**: 1 plan

Plans:
- [ ] 03-01: Refactor states and API bindings in `components/agent-client-page.tsx`.

---

### Phase 4: Smooth UI/UX Visual Polish
- **Goal**: Polish dashboard panels with smooth CSS micro-animations, loading skeletons, and layout transitions.
- **Depends on**: Phase 3
- **Requirements**: UI-02, UI-03, UI-04
- **Success Criteria**:
  1. Warm, responsive HSL tailored colors and premium typographic layout.
  2. Beautiful active-typing indicator animations and skeletons.
  3. Elegant visual card-to-PDF split panel transitions.
- **Plans**: 1 plan

Plans:
- [ ] 04-01: Implement CSS micro-animations, loading skeletons, and interactive state fades in the dashboard layout.

---

### Phase 5: Automated Testing & Verification
- **Goal**: Install and configure Vitest to test core business logic, converters, and model nodes in isolation.
- **Depends on**: Phase 4
- **Requirements**: TEST-01, TEST-02
- **Success Criteria**:
  1. Automated unit tests cover all lab tools, unit converters, and file processors.
  2. Mock-based graph simulation runs successfully with zero LLM network calls.
- **Plans**: 2 plans

Plans:
- [ ] 05-01: Configure Vitest and write unit tests for `lib/services/processing.ts` and `lib/agent/tools/lab-tools.ts`.
- [ ] 05-02: Build mock LLM graph simulation tests to verify node-to-node routing flows.
