<domain>
## Phase Boundary

Implement robust retry logic, request timeouts, and elegant error reporting in the chatbot workspace. The chatbot should elegantly handle and display messages for slow network responses, complete network disconnections, token limit exhaustion, and model timeout exceptions.

</domain>

<decisions>
## Implementation Decisions

### Timeout Handling
- **Slow response warning**: If the model API call takes longer than 15 seconds, show a subtle loading notice ("The medical brain is working on a complex response, please wait...").
- **Hard Timeout**: If the request takes longer than 35 seconds, abort the request and display a prominent warning block in the chat stream with a "Retry" button.

### Error Mapping & Display
- **Network Issue (Offline/Fetch error)**: If the client cannot connect to the server (e.g. `TypeError: Failed to fetch`), display: "Network connection lost. Please verify your internet connection and try again."
- **Capacity/Token Exhaustion**: If the API returns a status 429 or a rate-limit/token-quota error from the model provider, display: "Model capacity or token limit exceeded. Please try simplifying your prompt or wait a moment before retrying."
- **Generic Server Failures (500 errors)**: Display: "We encountered an unexpected issue connecting to the medical brain. Please try again."

### Retry Mechanics
- Clicking the "Retry" button on any error block should automatically resend the last prompt using the identical payload (including any attached file data).
- The retry action should clear the failed assistant message block and initiate a fresh loading/thinking state.

### the agent's Discretion
- Choice of exact CSS micro-animation classes (using Tailwind/Tailwind v4 classes).
- Toast messages vs inline chat bubble message blocks (inline message blocks are preferred for conversation flow).

</decisions>
