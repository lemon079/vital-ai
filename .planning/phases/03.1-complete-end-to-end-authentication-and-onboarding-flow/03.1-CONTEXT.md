# Phase 03.1: Complete End-to-End Authentication and Onboarding Flow - Context

**Gathered:** 2026-06-03
**Status:** Ready for planning
**Source:** User Request

<domain>
## Phase Boundary
This phase implements and enforces a secure, robust end-to-end authentication and onboarding flow in the application.

</domain>

<decisions>
## Implementation Decisions

### 1. Database Cleanup
- **Decision**: Clean/flush existing user and chat records from the database first, so we start with a clean state.

### 2. Login Restrictions
- **Decision**: Users must not be allowed to log in unless they already have a registered account (i.e. correct email and password validation). No guest accounts or auto-logins for un-registered emails.

### 3. Post-Login Redirects
- **Decision**: Immediately after a user successfully logs in, they must be redirected to the `/onboarding` page to complete their onboarding profile.

### 4. Auth Page Access Restrictions
- **Decision**: Logged-in users must be barred from visiting authentication pages (e.g., `/login`, `/register`). If they try to access these, they must be redirected away.

### 5. Onboarding Enforcement
- **Decision**: If a logged-in user has NOT completed onboarding yet, they must always be redirected to `/onboarding` first when trying to access `/agent` or any other app pages. Even if they return later (next day), they must go to `/onboarding` first.

### the agent's Discretion
- Implementation details of middleware or route guard redirections using Next.js middleware and cookies.
- Handling profiles database state for tracking the `is_onboarded` status.

</decisions>
